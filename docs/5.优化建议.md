# 后续优化建议

本文只记录当前尚未完成的改进项。已经落地的事务、outbox、自动重试、监控 freshness、指标、日志脱敏、迁移版本管理和生产静态文件服务不再列为建议，相关变化见项目根目录的 `CHANGELOG.md`。

## 优先级说明

- P0：影响数据正确性或核心服务连续性，应尽快处理。
- P1：明显提升可维护性、验证能力或运维效率。
- P2：当前 Tailscale 私网部署下风险较低，可按需要安排。

## P1：PostgreSQL 与浏览器集成测试

现有单元测试已覆盖解析、缓存、重试间隔、HTTP 参数和迁移文件发现，但关键跨组件流程仍缺少自动化验证。

建议增加：

- PostgreSQL：消息并发去重、事务回滚、附件补全、规则匹配、outbox 领取和失败重试。
- LISTEN/NOTIFY：消息、监控状态和通知事件的实时广播。
- Chrome/CDP：登录失效、页面重载、target 切换、连接中断恢复。
- WebSocket：真实升级、ping/pong、慢客户端和断线重连。

推荐在 CI 中使用临时 PostgreSQL，并将需要真实微博登录态的测试单独标记为手工或受保护环境测试。

## P1：通知失败人工补发与幂等键

通知已经支持自动重试和最终失败状态，但还缺少运维补发入口；如果企业微信中转服务已发送成功、而本地状态更新失败，也可能产生重复通知。

建议：

1. 增加失败 outbox 列表和详情 API。
2. 增加单条/批量重新入队操作，并记录操作者和原因。
3. 将 outbox ID 作为幂等键传递给中转服务。
4. 中转服务按幂等键保存短期发送结果，重复请求直接返回原结果。

## P1：通知规则管理页面

后端规则 API 已生效，但前端尚无可视化管理页面。

建议支持：

- 按微博群 ID、群名、发送人 ID、昵称和消息类型创建规则。
- 启用、停用和编辑规则。
- 显示规则最近命中时间、命中次数和最终失败数。
- 对“环境变量默认通知规则”提供只读来源提示，避免误删后被 monitor 再次同步。

## P1：CI 与发布流程

建议建立持续集成：

```bash
go test ./...
go vet ./...
cd frontend && npm ci && npm run build
bash -n scripts/*.sh
```

后续可增加：

- PostgreSQL 集成测试。
- Linux Chrome smoke test。
- 版本号和 Changelog 校验。
- Linux 二进制与前端构建产物发布。
- systemd 模板和迁移文件打包。

## P1：Prometheus 告警规则

`/metrics` 已提供所需指标，但尚未附带告警规则。建议至少配置：

- `weibo_assistant_monitor_fresh == 0` 持续 2 分钟。
- `weibo_assistant_monitor_cdp_connected == 0` 持续 2 分钟。
- notification failed backlog 大于 0。
- notification pending backlog 持续增长。
- 入库失败计数增加。
- monitor 指标更新时间超过预期。
- 内存、goroutine 或 tracked requests 持续异常增长。

## P2：Tailscale 内网安全复核

当前服务运行在受控的 Tailscale 私网，因此完整 API 鉴权暂不作为高优先级。但仍建议定期确认：

1. `6001`、`6002` 未通过公网安全组或路由器端口映射暴露。
2. 未启用 Tailscale Funnel，或 Funnel 未指向本服务。
3. Tailnet ACL/Grants 只允许可信设备访问。
4. Chrome DevTools 端口始终只绑定 `127.0.0.1`。
5. `.env` 和 `.weibo-profile` 权限保持为运行用户私有。

如果 Tailnet 引入共享用户、不受控设备或公网入口，应提升此项优先级，并增加 API Token、严格 Origin 白名单和反向代理 TLS。
